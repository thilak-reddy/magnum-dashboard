## Legend & Conventions

| Badge | Meaning | Notes |
|---|---|---|
| `PK` | Primary Key | All PKs are UUID, generated by `uuid_generate_v4()` |
| `FK` | Foreign Key | Column header shows referenced `table.column` |
| `UQ` | Unique constraint | May be single-column or part of a composite unique key |
| `NN` | Not Null | Column does not accept NULL |
| `nullable` | Accepts NULL | Column is optional |
| ⭐ NEW | Added in Day 6 migration | Tables or columns added during schema hardening |

**Column table format:** `#` · `column_name` · `type` · `nullable` · `default` · `PK` · `FK` · `UQ`

**Timestamps:** All mutable tables have `created_at timestamptz NOT NULL DEFAULT now()` and `updated_at timestamptz NOT NULL DEFAULT now()`. `updated_at` is maintained by database triggers. Immutable tables (audit logs, raw punches, check results) have `created_at` only.

**Soft deletes:** `employees` uses `deleted_at timestamptz` for soft deletion. All other tables use `is_active boolean` or status enums.

**month_year format:** All `month_year` columns store `'YYYY-MM'` (e.g. `'2026-02'`) as text for simple filtering without date arithmetic.

### `payroll_records`

Main payroll table — one row per employee per month. ## Row Level Security (RLS) Notes

RLS is enabled on all tables. Policies enforce factory-scoped access at the database level.

| Role | Access |
|---|---|
| `SUPER_ADMIN` | All rows across all factories and tables |
| `CENTRAL_HR` | All rows across all factories; cannot manage users |
| `FACTORY_HR` | Only rows where `factory_id` matches their assigned factory |
| `VIEWER` | Read-only access to all factories |

**Key policy:** `FACTORY_HR` users cannot see `employees`, `payroll_records`, `check_results`, `alerts`, or any other factory-scoped table for factories other than their own. This is enforced by Supabase RLS policies using `auth.uid()` joined against `user_profiles.factory_id` — not application-level filtering.

**Service role:** n8n uses the Supabase service role key, which bypasses RLS. The service role key is stored only in n8n's credential store and never in frontend code or source repositories.

## n8n Workflow Data Flow

### Daily workflow (cron: 06:00 AM)

```
Savior API → savior_raw_punches (write)
          → D01: count / timestamp / ID checks → check_results (write)
          → D02: punch validation              → check_results (write)
          → D03: attendance status             → attendance_processed (write)
          → D04: late/early detection          → attendance_processed (update)
                                               → monthly_attendance_summary (update)
          → alerts (write on FAIL)
          → n8n email node (send on CRITICAL/HIGH)
          → check_runs (update: completed_at, counts)
```

### Monthly workflow (cron: 1st of month, 08:00 AM)

```
Stage ERP API → payroll_snapshots (write)
              → payroll_records (write, one row per employee)
              → M05–M23: all monthly modules → check_results (write)
              → alerts (write on FAIL)
              → n8n email summary
              → check_runs (update)
```

### Annual workflow (cron: January 1st)

```
A24: lwf_deducted check           → check_results (write)
A25: bonus accrual sum vs paid    → performance_bonus_accrual (read/write)
                                  → performance_bonus_config (read)
A26: EL encashment audit          → el_balance (read/write)
A27: EPF/ESI vs ECR/Challan       → reconciliation_uploads (read)
                                  → check_results (write)
```

## Special Case Handling

| Scenario | Tables involved | Behaviour |
|---|---|---|
| **New joiner mid-month** | `employees`, `ctc_records`, `payroll_records` | Salary prorated from `date_of_joining`. Min wage checked on prorated basis. EPF/ESI registration must exist before first payroll — WARN if `uan_number` or `esi_number` is NULL. |
| **ESI salary crossing ₹21,000 mid-cycle** | `esi_cycle_enrollment` | ESI continues until cycle end. `esi_cycle_enrollment` records the qualifying gross and determination month. M11 enforces this — does not drop ESI mid-cycle. |
| **Comp-off hours** | `compoff_ledger`, `savior_raw_punches`, `attendance_processed` | Comp-off hours approved by factory manager via email. M22 checks that `compoff_hrs` in Savior punches do NOT flow into `ot_hours`. |
| **Designation / grade change** | `designation_history`, `minimum_wages`, `employees` | New designation changes minimum wage floor (M06) and incentive multiplier (M08). `designation_history` uses `effective_from` so the system applies the correct rule for the correct month. |
| **Long absenteeism** | `attendance_processed`, `alerts` | If an employee is continuously absent >10 days, a MEDIUM alert is raised with the employee list for HR review. |
| **Maternity** | `esi_cycle_enrollment`, `payroll_records` | If ESI enrolled, maternity pay is by ESIC — system flags employer as not liable. If not enrolled, employer pays 6 months salary — system verifies payment in payroll_records. |
| **Loan + 50% cap** | `loan_ledger`, `payroll_records` | M18 checks that all deductions (excluding advance) do not exceed 50% of earned gross. M14 checks EMI does not exceed outstanding balance. |
